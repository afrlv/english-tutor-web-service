## Проект
Веб-сервис для одного репетитора английского языка: кабинеты четырёх ролей (суперюзер, учитель, ученик, родитель), расписание уроков, ДЗ, учёт денег, ежедневный email-дайджест учителю. Vue 3 + PrimeVue (frontend), FastAPI async + PostgreSQL (backend), всё в Docker Compose.

## Команды
- `docker compose up -d` — поднять всё (postgres, backend :8000, frontend :5173); миграции и сид выполняются на старте backend автоматически.
- `docker compose exec backend pytest` — backend-тесты (нужен запущенный postgres; создают БД teacher_test).
- `docker compose exec backend alembic revision --autogenerate -m "..."` — новая миграция (файл появится на хосте через bind-mount).
- `cd frontend && npm test` / `npm run typecheck` — vitest и vue-tsc.
- Сид-учётки: admin@example.com / teacher@example.com, пароли в `.env`.

## Архитектурные решения (что и почему)
- **Деньги — неизменяемый леджер `transactions`** (charge при «урок проведён», payment вручную), долг и заработок только SQL-агрегатами. Отвергли хранение долга числом на карточке родителя: нет истории, легко рассинхронизировать. `transactions.lesson_id` UNIQUE — защита от двойного начисления; amount — снапшот цены на момент урока, смена цены не переписывает историю. **Эти инварианты не ломать** (`services/finance.py`, тесты в `test_finance.py`).
- **Одна карточка родителя на ученика** (`parents.student_id` UNIQUE) — иначе леджер не знает, чью цену брать. Если понадобится второй родитель — сначала решить, кто «плательщик».
- **Auth: JWT в httpOnly cookie (SameSite=Lax), 24ч, без refresh** — stateless, нет таблицы сессий и токена в localStorage. Отвергли refresh-токены как лишнее. Отзыв сессий — через `users.token_version` (вшит в токен как `tv`): инкремент при смене/сбросе пароля и деактивации инвалидирует все прежние токены, текущему клиенту сразу выдаётся свежий. `JWT_SECRET` по умолчанию `dev-secret`; при `DEV_MODE=false` дефолт запрещён — `get_settings()` падает на старте.
- **Почта**: настройки в БД (`email_settings`, синглтон id=1, правится в кабинете администратора `/admin/email`), env `EMAIL_BACKEND`/`SMTP_*` — только дефолт до первого сохранения. Бэкенды: `console` (письма в лог) и `smtp` (aiosmtplib; порт 465 = implicit TLS, иначе STARTTLS). Вся отправка — через `services/mailer.send_email(db, …)`: пишет результат в журнал `email_log`, ошибка отправки не роняет сценарий (создание ученика пройдёт, ошибка видна админу в журнале). Пароль SMTP наружу из API не отдаётся (`password_set: bool`; пустой пароль в PUT = не менять). Напоминания ученикам: джоба раз в 15 мин, окно `REMINDER_HOURS`, отметка `lessons.reminder_sent_at`; при ошибке отправки отметка не ставится — джоба повторит. Письма родителям о деньгах: долг ≥ 2 уроков → письмо (ежедневно в 10:00, повтор раз в 7 дней через `parents.debt_notice_sent_at`, сброс при погашении — отвергли «писать при каждом начислении» как спам); выписка за прошлый месяц 1-го числа, месяцы без активности пропускаются.
- **Приватная заметка учителя** (`students.teacher_private_note`) скрыта от ученика/родителя только тем, что не входит в их pydantic-схемы — при новых эндпоинтах следить, чтобы не утекла (тест `test_private_note_hidden_from_student_and_parent`).
- **Часовой пояс**: расписание, слоты, дайджест и напоминания считаются в `TZ` из `.env` — сейчас Asia/Yekaterinburg (UTC+5), как у машины оператора и самого учителя. При «уроки не попали в дайджест» первым делом проверять TZ — стреляло при отладке, когда стоял Europe/Moscow.
- **Мягкое удаление учёток** (`users.deleted_at`): жёсткое удаление невозможно — на `users` завязаны леджер, уроки, комментарии через FK, каскад разрушил бы неизменяемую историю денег. `DELETE /admin/users/{id}` (суперюзер, нельзя себя) ставит `deleted_at`, `is_active=False`, инкрементит `token_version`. Удалённый скрыт везде, где показываются активные (login, admin-список, impersonation, списки учеников/родителей учителя, finance/calendar/digest/dashboard), но строки в БД целы — для аудита и возможного восстановления (снять `deleted_at`). Фильтр `User.deleted_at.is_(None)` — общий инвариант активных выборок. Восстановление: `GET /admin/users/deleted` + `POST /admin/users/{id}/restore` (снимает `deleted_at`, снова активна; 409 если почту/логин занял активный). Маршрут `/users/deleted` объявлен ДО `/users/{user_id}`, иначе «deleted» попадёт в параметр пути.
- **Мультиарендность (SaaS, путь B)**: арендатор — учитель. `students.teacher_id` (NOT NULL) — ученик принадлежит ровно одному учителю; email ученика уникален в системе. Изоляция в API — **default-deny**: хелперы `get_*_or_404` принимают `current_user`, для учителя фильтруют по цепочке до `teacher_id` и отдают **404 на чужое** (не 403 — не раскрываем существование); суперюзер видит всех. Списки (`/students`, календарь, `/finance/summary`, дайджест) фильтруются по `teacher_id`. Создавать учеников может только учитель (суперюзер — через режим просмотра). Почта (`email_settings`) пока глобальная, платформенная — per-teacher SMTP отложен до биллинга. Учителей заводит суперюзер вручную (публичный signup и тарифы — отдельные этапы). Инвариант «учитель не видит чужих арендаторов» проверяется `test_multitenancy.py` — не ломать.
- **Файлы — только через `/api/files/{path}`** с проверкой прав; публичный `StaticFiles`-маунт снят. Файл ищется в БД по точному `file_path` (это и авторизация, и защита от обхода каталога — на диск идём только за найденной записью). Доступ: суперюзер, учитель-владелец, сам ученик, его родитель (аватары). Ссылки на фронте — `/api/files/...`, не `/media/...`. Загрузки проверяются по сигнатуре (`services/file_signatures.py`) — заявленный content-type сверяется с реальными байтами. Cookie-флаг `Secure` — через `SECURE_COOKIES` (в проде true за HTTPS).
- **Карточка урока — центральная сущность UX**: учитель (`/lessons/:id`) и ученик (`/my-lessons/:id`) работают с уроком на единой странице (материалы `lesson_attachments`, ДЗ с вложениями/ответом/оценкой, статусные действия). Отвергли «всё в таблице уроков»: вложенный редактор ДЗ в ячейке таблицы не масштабировался. Списки уроков — навигация, содержимое — в карточке.
- **Карточки для запоминания (Quizlet)**: наборы `card_sets` + `cards` на ученика; счётчики `times_correct`/`times_wrong` на самой карточке, «выучена» при `times_correct >= LEARNED_THRESHOLD` (2). Отвергли отдельную таблицу попыток: для одного ученика на карточку достаточно счётчиков, прогресс — агрегат на лету. Учитель ведёт наборы, ученик отвечает (`POST /me/cards/{id}/answer`); сверка в режиме ввода — без учёта регистра/ё/пробелов на фронте.
- **Отмены/переносы**: статус урока меняется только явными действиями (conduct/revert/cancel/restore), поле `status` из PATCH убрано. Тип отмены `cancellation_kind` (teacher/student — бесплатно, late — charge на `charge_amount` или полную цену; та же `transactions.lesson_id` UNIQUE защищает от двойного начисления). Restore удаляет charge и чистит причину. Перенос = PATCH `scheduled_at`; `rescheduled_from` хранит только ПЕРВОЕ исходное время (история цепочки переносов не нужна — важно «откуда сдвинули» относительно договорённости).
- **Повторяющееся расписание — материализация**: слоты `schedule_slots` (день недели + время в TZ) порождают реальные строки `lessons` на `GENERATE_WEEKS` (4 нед.) вперёд; догенерация ночью в 03:00 и при старте backend. Отвергли «виртуальные» повторения: леджеру и conduct/revert нужны настоящие уроки. Уникальность `(lesson.slot_id, slot_date)` — перенесённый/отменённый урок серии не пересоздаётся. Удаление слота — soft (`is_active=False`), сносятся только будущие planned-уроки; проведённые и история денег неприкосновенны.
- **Логин отделён от почты** (`users.login`, unique): вход работает и по логину, и по почте (`/auth/login` принимает поле `login` с любым из них). У существующих и автосоздаваемых пользователей логин по умолчанию равен почте. Отвергли «логин = почта навсегда»: суперюзеру нужно выдавать короткие логины, не трогая контактную почту для рассылок.
- **Просмотр от имени (impersonation)**: суперюзер получает cookie с токеном целевого пользователя + claim `imp_by` (id суперюзера). Отвергли фронтовый «view as role» без смены токена — RBAC на backend всё равно режет чужие эндпоинты. Переключение между профилями = `stop` + `impersonate` (начать просмотр может только настоящий суперюзер; цепочки `imp_by` запрещены). `/auth/impersonation/targets` доступен и в режиме просмотра — иначе строке-переключателю неоткуда взять список.
